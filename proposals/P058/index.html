回首頁 / AI 組合企劃 / P058

小紅書種草內容中台：關鍵字選題 → 繁中／簡中筆記文案＋封面圖 → 人工確認後發佈與數據回收，一人維運多個帶貨帳號

小紅書是華語圈目前轉換率最高的圖文種草場，但它的內容規則和其他平台完全不同——標題吃搜尋關鍵字、首圖決定八成點擊、正文要像真人分享而不是廣告，所以「一稿多平台分發」在這裡一定失效；本案圍繞今日新上榜、一萬五千顆星的 xiaohongshu-mcp，做一條專屬小紅書的內容流水線：從平台內搜尋關鍵字反推選題，到符合平台語感的筆記文案與封面圖，再到人工確認後的發佈與成效回收，讓一個人能同時養十個以上的帶貨帳號。

難度: medium 估 3–5 週做出能跑版本：接上 xiaohongshu-mcp 並把搜尋與筆記讀取跑通、同時把發佈設成需人工確認的雙軌流程約 1 週；keywordpro 與平台內搜尋的雙來源選題表約 0.5 週；Easel 的內容草案管線與帳號人設設定約 1 週；GLM-5.3-Flash 的語感打磨與繁簡互轉約 0.5 週；Mage-Flow 封面模板與文字疊排約 1 週（視覺一致性最花時間，必須反覆調模板）；成效回收與選題權重調整約 0.5 週。難點有四：一是帳號風控——自動化操作是本案最大的營運風險，必須把頻率上限、隨機間隔、單帳號每日操作上限做成產品的硬限制而非可調參數，並在服務條款中明確要求客戶自行確認其使用方式符合平台規範，本產品不對帳號狀態作任何保證；二是平台改版——小紅書介面與風控策略會不定期調整，上游 MCP 工具的可用性因此有斷裂風險，必須把 ego-lite 的登入態瀏覽器路徑當成備援而非附加功能，並把『上游壞掉時降級成純草稿產出、由人手動貼上發佈』設計進去，讓服務不至於整條停擺；三是語感的評分很主觀，早期只能靠人工挑選並累積偏好樣本，建議前兩個月的所有成稿都保留人工修改前後的對照，累積到一定量後才有辦法把偏好固定成規則；四是合規與揭露——帶貨內容在多數市場都要求標示為廣告或合作，模板必須內建揭露語句，商業化前應就目標市場的廣告揭露規範取得正式意見，本文件不構成法律建議。

怎麼變現

①內容代操月費為主力，也是最快能收到錢的一條：依『帳號數 × 每月篇數 × 是否含封面圖設計』分級報價，中小電商與個人品牌最痛的是「知道要經營小紅書但沒有人天天寫」，代操把這件事外包掉；報價時把選題報告獨立成可交付物，讓客戶即使不續約也留下一份關鍵字資產，這反而提高續約率。②自助版 SaaS 月費：把同一套流水線做成客戶自己操作的介面，依每月生成篇數與可綁定帳號數分三級，免費層每月給少量篇數做導流；自助版與代操並不衝突，自助版是代操客戶的降級承接口，也是代操的漏斗上游。③選品聯盟佣金分潤：內容中台本身就掌握「哪個選題帶來多少點擊與私訊」的資料，把電商平台的聯盟連結接進流程，替自營帳號賺商品佣金，並對代操客戶提供『佣金分潤制』方案——不收月費、只抽帶貨佣金，這個方案專門用來拿下不願付固定費用的中小賣家。④教學與工具內容站：『小紅書關鍵字怎麼選』『封面圖點擊率怎麼提』這類長尾教學自成一個內容站，網頁端掛 Adsterra／Monetag 賺廣告費並替主產品導流，開源的排程與素材整理工具在說明頁放 Ko-fi 收贊助。⑤本機版 Mac App 買斷：在意帳號登入資訊不上雲的個人創作者與工作室，賣一次性買斷的本機版，安裝說明頁導購 NAS 與 VPS 走主機商聯盟。全案不涉及任何 VPN 類聯盟。

運作方式

整條流水線分成六層，核心設計原則是『平台專屬、人工把關』——小紅書的內容規則與帳號風控都與其他平台不同，所以價值不在跨平台通用，而在把單一平台的規則吃透，並且在真正送出前一定經過人審。接口層：github:xpzouying/xiaohongshu-mcp 是本案的地基，它把小紅書的搜尋、筆記讀取、發佈等操作包成 MCP 工具，讓 AI agent 能以結構化方式和平台互動，省下自己逆向平台介面的全部工夫；本案對它的用法有兩個關鍵取捨，一是只把『搜尋與讀取』設為 agent 可自動執行，『發佈』一律要人在介面上按下確認才送出，二是所有帳號操作都設頻率上限與隨機間隔，寧可產能低也不要讓客戶帳號進風控名單——這條規則直接寫進產品，不給使用者調快的選項。登入態層：github:citrolabs/ego-lite 是給 AI 用的瀏覽器，能沿用使用者既有的登入狀態，本案用它處理 MCP 工具覆蓋不到的頁面，例如創作者後台的成效數據、筆記的曝光與收藏明細、以及平台不時改版的新版介面；把它和 MCP 分工的理由是：結構化操作走 MCP 比較穩，讀後台圖表與非公開頁面則需要真實登入態的瀏覽器，兩者互補而非替代。選題層：github:AgriciDaniel/keywordpro 是本地優先的關鍵字研究工具，負責把『我要賣這個品類』轉成一份可執行的選題表——本案的做法是雙來源交叉：一路用 keywordpro 產出關鍵字的搜尋量與競爭度、做成主題群組；另一路用 xiaohongshu-mcp 直接在平台內搜同一批關鍵字，抓回排在前面的高互動筆記，拆解它們的標題句式、正文結構、標籤組合與封面風格。真正決定選題的是第二路——平台內的實際表現遠比通用關鍵字工具的估計值準，keywordpro 的作用是提供可長期累積、可交付給客戶的關鍵字資產結構。趨勢與內容層：github:ZJU-REAL/Easel 是開源的社群媒體代理，本身就同時具備趨勢發現與內容創作能力，本案把它當成選題到成稿之間的引擎——輸入是選題表加上該關鍵字下的高互動筆記樣本，輸出是含標題候選、正文骨架、標籤組合與配圖指示的內容草案，並由它負責追蹤品類內正在起量的新話題，讓內容日曆能隨趨勢滾動而不是月初排完就固定。語感層：hf:model:zai-org/GLM-5.3-Flash 負責最後的文字打磨，這層之所以獨立出來，是因為小紅書的語感是產品成敗的分水嶺——太像廣告文案會被使用者直接滑掉，必須是第一人稱的真實使用感受、有具體場景與細節、有缺點也講。這個模型中英雙語穩且是輕量快速版本，適合每篇都要跑好幾個版本的高頻工作；同時由它處理繁中與簡中的互轉，讓台灣賣家的素材能改成大陸市場的用語，或反過來。視覺層：hf:model:microsoft/Mage-Flow 是可商用的文生圖模型，負責小紅書最關鍵的封面圖——做法是先為每個帳號固定一套視覺模板（配色、字級、版式、留白比例），再讓模型只生成底圖，標題文字用程式排版疊上去，這樣才能同時保有帳號的視覺一致性與封面文字的可讀性；每篇同時產三張不同構圖的候選封面，讓營運者挑，這一步的人工介入報酬率最高。數據回流層：發佈後定期回收每篇的曝光、點擊、收藏與私訊數，寫回選題表，讓下一輪選題能依實際成效調整權重，這份『哪些關鍵字真的帶來私訊』的累積資料就是代操服務最難被取代的資產，也是漲價的依據。與現有企劃的區隔：P043 帳號矩陣分發中台做的是『一稿改寫成各平台原生版本並排程分發』，價值在跨平台的量；本案完全相反，是單一平台的深度——平台內搜尋反推選題、平台專屬的語感與封面規則、平台後台的成效回流，這些在跨平台工具裡做不了，元件也完全不重疊。P053 聯盟評測站群工廠賣的是自有網站的長文與外鏈，流量來自搜尋引擎；本案的流量來自平台內的推薦與搜尋，不涉及建站。P056 跨境電商私域客服處理的是私訊進來之後的售前售後對話，本案負責的是把人帶到私訊之前的那一段，兩案互為上下游而非重疊。
